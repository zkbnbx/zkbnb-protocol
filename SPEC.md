# zkBNB — Plant a coin. Grow it in BNB. Harvest it shielded.

A BNB Smart Chain port of [sapling.cash](https://sapling.cash) (Zcash-native launchpad on
Solana) with three changes:

1. **Chain + quote asset**: BNB Smart Chain (mainnet 56 / testnet 97); every coin is paired
   to native BNB instead of ZEC. Bonding curve is our own contract (pump.fun has no BNB
   deployment); graduated coins migrate to PancakeSwap V2 and keep collecting the creator fee
   through a 2% pair-tax on the token.
2. **zk privacy**: a Groth16 shielded BNB pool (Poseidon Merkle tree, 2-in-2-out join-split,
   tornado-nova style). Harvests, holder rewards and donations can be paid as shielded notes;
   anyone can shield / unshield / privately transfer BNB on `/move`.
3. **Donation system**: the deployer's 0.80% can be routed to a *donation ring*. Each epoch
   the accumulated BNB rotates to the next cause in the ring and is paid as a shielded note
   to the cause's published shielded key. Anyone can donate publicly or privately.

Everything below is the contract between `contracts/`, `circuits/`, `keeper/` and `web/`.

## 3. Contracts

All amounts in wei. `BPS = 10_000`. Creator fee `FEE_BPS = 200` (2.00%).

### 3.1 GroveCoin (ERC-20)

- `name`, `symbol`, `decimals = 18`, `TOTAL_SUPPLY = 1_000_000_000e18`, all minted to
  `Launchpad` at creation. `burn(amount)` and `burnFrom`.
- `pair` (PancakeSwap V2 pair, set once by `Launchpad` on graduation), `router`, `feeRouter`.
- Pair-tax: in `_update`, if `pair != 0` and (`from == pair` or `to == pair`) and neither side
  is exempt (launchpad, roots, feeRouter, router during migration), take `FEE_BPS` of the
  amount into the coin contract itself (`accruedTax`).
- `sweepTax(minOut)`: anyone; swaps `accruedTax` tokens for BNB on the router
  (`swapExactTokensForETHSupportingFeeOnTransferTokens`) and calls
  `feeRouter.collect{value}(coin)`. Emits `TaxSwept(tokens, bnb)`.
- Metadata: `image`, `description`, `website`, `twitter`, `telegram` strings stored on the
  Launchpad's `CoinInfo`, not here.

### 3.2 Launchpad

Constant-product curve with virtual reserves (pump.fun shape, BNB-scaled):

```
VIRTUAL_BNB      = 4 ether
VIRTUAL_TOKENS   = 1_073_000_000e18
CURVE_TOKENS     = 793_100_000e18        // sold on the curve
LP_TOKENS        = TOTAL - CURVE_TOKENS  // 206.9M, paired with raised BNB on graduation
k = (VIRTUAL_BNB + realBnb) * (VIRTUAL_TOKENS - soldTokens)
// the curve is complete when soldTokens == CURVE_TOKENS, which takes 11.334047874240800286 BNB net
// of fee (11.5654 BNB gross); start price 3.73e-9 BNB, end price 5.48e-8 BNB (x14.7)
```

- `plant(PlantParams{name, symbol, description, image, website, twitter, telegram,
  payoutMode, payoutWallet, ringId}) payable` — charges `plantFee`; optional first buy with
  the remainder of `msg.value`; emits `Planted(coin, creator, ...)`. Calls
  `feeRouter.registerCoin(coin, creator, payoutMode, payoutWallet, ringId)`.
- `buy(coin, minTokensOut) payable`: fee = `msg.value * 200 / 10_000` sent to
  `feeRouter.collect{value: fee}(coin)`; the rest buys along the curve. Emits
  `Trade(coin, trader, isBuy, bnbIn, tokensOut, priceAfter)`.
- `sell(coin, tokensIn, minBnbOut)`: tokens returned to the curve, gross BNB out computed,
  fee = 2% of gross → `feeRouter.collect`, net to seller.
- `buyCount(coin)`, `stage(coin)`: `0 Seed (<10 buys)`, `1 Sapling`, `2 Orchard`.
- Graduation (inside `buy` when `soldTokens >= CURVE_TOKENS`): get-or-create the pair, and if
  someone pre-seeded it, first arbitrage it to the conservation ratio with the coin's own
  BNB/tokens; then transfer all tokens and BNB (as WBNB) to the pair and `mint(0xdead)`. The
  router's `addLiquidityETH` is not used, so a pre-created pair can neither brick graduation nor
  drain the raise. Emits `Graduated(coin, pair, bnb, tokens)`.
- `quoteBuy(coin, bnbIn)`, `quoteSell(coin, tokensIn)`, `price(coin)`.
- `CoinInfo { creator, createdAt, realBnb, soldTokens, buys, sells, pair, metadata… }`.
- Admin: `setPlantFee`, `setTreasury`. `plantFee` goes to `feeRouter.treasury()`.

### 3.3 FeeRouter

Receives every creator fee (`collect(coin) payable`, callable by the coin's launchpad or
the coin itself) and splits it immediately:

```
rootsShareBps     = 2500   (of the fee)  → Roots.deposit{value}(coin)
rootstockShareBps = 2500                 → rootstockPot (buy+burn $ZKBNB)
treasuryShareBps  = 1000                 → treasury
deployerShareBps  = 4000                 → by payoutMode
Bounds (admin-settable): rootsShareBps >= 2500, treasuryShareBps <= 2000, sum == 10_000.
```

`PayoutMode { Creator, Wallet, Holders, Donate }`

- `Creator`: pushed to `creator` (pull-pattern `pending[addr]` if push fails).
- `Wallet`: pushed to `payoutWallet`. Setting it hands control over permanently.
- `Holders`: accumulates in `HolderRewards.pot[coin]` via `holderRewards.fund{value}(coin)`.
- `Donate`: `donationRotator.fund{value}(coin)`; the coin's `ringId` picks the ring.

Rootstock: `buybackAndBurn(minOut)`; anyone; uses `rootstockPot` to buy `$ZKBNB` (on the
Launchpad curve if not graduated, else on the router) and burns it. `$ZKBNB` itself is a
GroveCoin flagged `isRootstock`: its whole fee goes to treasury (as on Sapling).

Events (feed Rings): `FeeCollected(coin, amount, source)`, `FeeSplit(coin, roots, rootstock,
treasury, deployer, mode)`, `Buyback(bnbIn, groveBurned)`, `PayoutModeHandedOver(coin, mode,
wallet, ringId)`.

Admin (owner, intended to be a multisig): shares within bounds, treasury, pause roots per
coin (recovery path to a fixed `recoveryAddress`), set rootstock coin once, `setModules` once,
`setKeeper`. Public (non-keeper) `buybackAndBurn` is capped at `publicBuybackCap` per block and
public `GroveCoin.sweepTax` at 1% of the pair's token reserve per block, so a caller-supplied
`minOut` of 0 cannot be sandwiched for more than dust; the keeper is uncapped and quotes off-chain.

### 3.4 Roots

- `balance[coin]`, `cap` (default 50 ether). `deposit(coin) payable` (only FeeRouter); any
  amount above cap is forwarded to `HolderRewards.fund(coin)` so nothing is lost.
- `harvestValue(coin, tokens) = balance[coin] * tokens / IERC20(coin).totalSupply()`.
- `harvest(coin, tokens, minBnb)`: `burnFrom(msg.sender, tokens)` then pay to sender.
  Emits `Harvested(coin, harvester, tokens, bnb, shielded=false)`.
- `harvestShielded(coin, tokens, minBnb, shieldedPubKey, blinding)`: same, but pays via
  `pool.depositFor{value}(pubKey, blinding)`. Emits `Harvested(..., shielded=true)`; the
  harvester's wallet is still visible on this tx (they signed it) — what becomes private is
  where the BNB goes afterwards. Docs must say this plainly.
- Dust guard: revert if `bnb == 0`.
- Invariant: the roots/supply ratio never decreases from a harvest.

### 3.5 ShieldedPool (zk)

Fixed design, matching `circuits/transaction.circom`:

```
Field          BN254 scalar field
Hash           Poseidon (circomlib)
Note           commitment = Poseidon(amount, pubKey, blinding)
Keypair        privKey (random field element); pubKey = Poseidon(privKey)
Nullifier      Poseidon(commitment, leafIndex, signature), signature = Poseidon(privKey, commitment, leafIndex)
Tree           depth 20, incremental, 100-root history, zero leaf = keccak("grove") % p
Join-split     2 inputs → 2 outputs; publicAmount = sum(out) - sum(in) + fee (mod p)
Public inputs  root, publicAmount, extDataHash, inNullifier[2], outCommitment[2]
```

- `transact(Proof, ExtData)`:
  `ExtData { recipient, extAmount(int256), relayer, fee, encryptedOutput1, encryptedOutput2 }`.
  `extAmount > 0` = deposit (`msg.value == extAmount`), `< 0` = withdraw to `recipient`,
  `0` = private transfer. `fee` goes to `relayer`. `publicAmount = extAmount - fee (mod p)`.
  `extDataHash = keccak(abi.encode(extData)) % p`. Nullifiers marked spent; commitments
  inserted; emits `NewCommitment(commitment, index, encryptedOutput)` and `NewNullifier`.
- `depositFor(pubKey, blinding) payable`: computes `commitment = Poseidon(msg.value, pubKey,
  blinding)` **on-chain** (Poseidon T4 bytecode), inserts it and emits
  `NewCommitment(commitment, index, encryptedOutput="")` plus `DepositFor(pubKey, amount,
  blinding, index)`. Used by Roots, HolderRewards and DonationRotator so contracts can pay
  into the pool without a proof. The amount and pubKey are public on that transaction; the
  note is unlinkable from then on (only the holder of `privKey` can produce its nullifier).
- Limits: `maxDeposit` (default 100 BNB, applies to `transact` deposits only, owner-settable via
  `setMaxDeposit`); `maxExtAmount` and `maxFee` are constants so the owner can never freeze
  withdrawals. `depositFor` has no cap so contract payouts can never be blocked. `pubKey == 0`
  and `fee > 0 with relayer == 0` are rejected (would burn funds).
- Tree capacity is 2^20 leaves (~500k transactions). When fewer than 2 slots remain, `transact`
  still pays out but emits `CommitmentDropped` instead of inserting: withdraw-only mode, never
  locked. Clients must not create non-zero outputs once `nextIndex() + 2 > 2^20`.
- No admin over funds.
- **Relayer** (`web/src/app/api/relay/route.ts`, server env `RELAYER_PRIVATE_KEY`): `GET` quotes
  `{relayer, fee}` (fee = gasPrice × `RELAY_GAS_UNITS` × (1 + `RELAY_MARGIN_BPS`/10⁴) +
  `RELAY_FLAT_FEE_WEI`); the browser proves with that `relayer`/`fee` in `ExtData`, `POST`s
  `{chainId, proof, extData}` (uints as decimal strings) and the relayer submits `transact` from
  its own wallet after `estimateGas` succeeds and `fee ≥ gas × gasPrice`. Only `extAmount ≤ 0`
  is relayed. The user's wallet is then absent from the transaction; the relayer can only
  decline, never redirect funds (everything is bound by `extDataHash`). Without the env var
  the endpoint answers `{ok:false}` and the UI sends from the user's wallet.
  Two more request kinds serve the dark pools (§3.9), discriminated by `kind` (default
  `"transact"`): `kind:"fill"` adds `order` and the relayer sends `DarkPool.transactAndFill`
  after checking `extData.recipient == darkPool.vaultFor(order)` and `extAmount == -order.bnbIn`;
  `kind:"vault"` carries `{vault, data, fee, deadline, sig}` and the relayer sends
  `DarkVault.relay` after checking `darkPool.isVault(vault)`. Quotes take the same `kind`
  (`RELAY_GAS_UNITS_FILL`, default 2.3M; `RELAY_GAS_UNITS_VAULT`, default 450k) and answer
  `{ok:false}` for `fill`/`vault` when the chain has no `darkPool`. Dark-pool buys have no
  wallet fallback: a wallet-sent fill would put the wallet on the trade.
- **Denominations** (`web/src/lib/zk/denominations.ts`): the UI steers shields and unshields to
  0.01 · 0.02 · 0.05 · 0.1 · 0.2 · 0.5 · 1 · 2 · 5 · 10 BNB and warns on other amounts, since
  edge amounts are public and a unique one links a shield to its unshield.

Poseidon: `contracts/poseidon/PoseidonT3.bin` (2 inputs, tree) and `PoseidonT4.bin`
(3 inputs, commitment) generated by `circomlibjs.poseidonContract.createCode(n)`; deployed in
`Deploy.s.sol` and tests with `CREATE`.

### 3.6 HolderRewards

- `pot[coin]` funded by FeeRouter (and Roots overflow).
- `postRun(coin, root, amount, holders, uri)`: keeper only; moves `amount` from `pot[coin]`
  into `runs[coin][runId] = {root, amount, claimed, holders, uri, postedAt}`. `uri` points to
  the published snapshot JSON (who/how much) so Rings can show it.
- `claim(coin, runId, amount, proof[])`: Merkle leaf `keccak(abi.encode(coin, runId,
  msg.sender, amount))`; pays `msg.sender`.
- `claimShielded(coin, runId, amount, proof[], pubKey, blinding)`: same, pays via
  `pool.depositFor`.
- `sweepExpired(coin, runId)`: after `claimWindow` (default 30 days), unclaimed goes back to
  `pot[coin]`.
- Keeper eligibility rule (off-chain, published): ≥ `minHolding` of the coin (default worth
  ~ $20), excludes pair, launchpad, roots, dead, and zkBNB wallets. Snapshot time is random
  within the hour after the pot crosses `minPot`.

### 3.7 DonationRotator — "rotate fees to others with zk payments"

- `Cause { name, uri, shieldedPubKey, encryptionKey, fallbackWallet, owner, active }`;
  `registerCause(...)` open to anyone (small anti-spam fee to treasury); `updateCause` by the
  cause owner only; the contract owner can only `setCauseActive` (moderation). Payouts that the
  pool or the fallback wallet refuse go to `pending[...]` (`withdrawPending`) so a ring can
  never be bricked. `epochLength` is bounded by `MAX_EPOCH = 365 days`.
- `Ring { causeIds[], epochLength, cursor, createdAt }`; `createRing(causeIds, epochLength)`
  open to anyone; ring 0 is the global ring maintained by the operator. Rings are immutable
  after creation (a coin's choice is irrevocable, like Sapling's handover).
- `fund(coin) payable` (FeeRouter): adds to `pot[ringId]`, where `ringId = coinRing[coin]`.
- `donate(ringId) payable`: public donation into a ring's pot. `donateToCause(causeId)
  payable`: direct public donation, paid as a shielded note immediately.
- `settle(ringId)`: anyone, once per epoch (`block.timestamp >= lastSettled + epochLength`):
  takes the whole `pot[ringId]`, pays it to `causes[ring.causeIds[cursor]]` via
  `pool.depositFor{value}(cause.shieldedPubKey, blinding)` where
  `blinding = uint256(keccak(ringId, epoch, cause)) % p`, advances `cursor`
  (round-robin). If the cause has no shielded key, pays `fallbackWallet` publicly.
  Emits `Settled(ringId, epoch, causeId, amount, shielded, leafIndex)`.
- Private donations from inside the pool are just a `transact` to the cause's pubKey; the web
  UI exposes this as "Donate privately" on `/donate`.

### 3.8 Trust model (to be stated on the docs page)

- Roots payouts, harvests, pool transfers and donation settlement are enforced on-chain.
- Holder-reward *allocation* is computed by the keeper (as on Sapling) and only its Merkle
  root is on-chain; every snapshot is published and checkable on Rings.
- Shielded notes hide the spending graph, not the deposit transaction. A harvest or claim
  into the pool shows the amount and destination pubKey; what happens next is private.
- Admin (multisig) can: change shares within bounds, pause a coin's roots and move them to
  the fixed recovery address, set the keeper, set pool limits. Admin cannot: take roots BNB,
  change a coin's payee after handover, spend pool notes, touch a dark vault (§3.9: no admin;
  each vault obeys only its own owner key), upgrade contracts (none are upgradeable).

### 3.9 DarkPool / DarkVault — trade from inside the pool

Design authority: `privacy/DARKPOOL-SPEC.md`. No new circuit, ceremony or change to a deployed
contract; neither contract has an admin (a vault has an `owner`, the user's per-vault key, nobody else).

- `DarkVault` (implementation, cloned per order with `Clones`): `initialize(owner, coin)` once
  by the factory; `buyFromFactory(bnbIn, minTokensOut, deadline)` (factory only); owner path
  `buy`, `sell(tokens, minBnbOut, pubKey, blinding)`, `harvest(tokens, minBnb, pubKey, blinding)`,
  `shield(amount, pubKey, blinding)` (0 = whole balance), `exec(target, value, data)`; buys go
  through `Launchpad.buy` on the curve or the Pancake router after graduation, and everything
  that leaves pays `pool.depositFor{value: proceeds - fee}(pubKey, blinding)`, never a wallet.
  `relay(data, fee, deadline, sig)`: anyone submits, the owner signed (EIP-712
  `Relay(bytes data,uint256 fee,uint256 deadline,uint256 nonce)`, domain `zkBNB DarkVault/1`),
  sequential `nonce`, the submitter is paid `fee` from the vault; `relay`/`initialize`/
  `buyFromFactory` cannot be the inner call.
- `DarkPool` (factory): `Order{coin, bnbIn, minTokensOut, owner, deadline, nonce}`;
  `vaultFor(order)` = `CREATE2` address with salt `keccak(abi.encode(order))`, so the recipient
  of a withdrawal proof binds the whole order. `transactAndFill(proof, extData, order)`: requires
  `extData.recipient == vaultFor(order)` and `-extAmount == bnbIn`, runs `pool.transact`, clones
  and initialises the vault, buys; any failure reverts everything (nullifiers unspent).
  `fill(order)`: lenient path once the vault address is funded; a failed buy leaves the BNB in
  the vault for `relay(buy)` / `relay(shield)`. `isVault`, `vaultCount`, `VaultCreated` event.
- Vault owner keys (`web/src/lib/darkpool.ts`): secp256k1 key `i` =
  `keccak256(bytes32(shieldedPrivkey) ‖ "zkBNB dark vault v1" ‖ uint32(i))`, derived on demand,
  never stored; the shielded key alone recovers every vault (scan `VaultCreated` for own owners).
- Privacy (must be stated this way on `/docs/darkpool`):

  | Hidden | Public |
  |---|---|
  | The wallet and shielded key behind a buy, sell, harvest or shield-back (only EOA: the relayer; the way back still names the pubKey) | Every buy: coin, BNB amount (an unshield), vault address, tokens received, time |
  | Which note paid for a buy; what is done with the proceeds note after it is created (the note's amount, pubKey and blinding are public in `DepositFor`) | Every sell / harvest / shield-back: vault, amount, `DepositFor` pubKey (the UI uses the user's own key, so all vault proceeds land on one pubKey; a Poseidon image, not a wallet, but a wallet-signed `harvestShielded` / `claimShielded` / `registerCause` carrying it, before or after, ties that wallet to every paid-out vault). The proceeds amount is odd and public: unshielding exactly it to a wallet matches the vault |
  | A link between two vaults of one person before they pay out (fresh owner key per vault; only timing / amount heuristics); after a sell / harvest / shield-back they are linked by the shared `DepositFor` pubKey | The relayer learns the client IP, the order and the pubKey on vault calls, not the wallet; it can decline, delay or front-run within slippage, never redirect. Non-standard BNB amounts, or a buy of the amount just shielded, link a shield to the buy: the UI steers to the denominations above |

  Later: hiding the amount or coin of a buy (multi-asset circuit + ceremony), reward claims from
  a vault in the UI (possible via `exec`), a relayer network.

## 4. Circuit (`circuits/transaction.circom`)

tornado-nova shape, `levels = 20`, `nIns = 2`, `nOuts = 2`:

```
signal input root; publicAmount; extDataHash;
signal input inputNullifier[2]; inAmount[2]; inPrivateKey[2]; inBlinding[2];
             inPathIndices[2]; inPathElements[2][20];
signal input outputCommitment[2]; outAmount[2]; outPubkey[2]; outBlinding[2];
```

Constraints: each input's commitment recomputed and (if amount ≠ 0) proven in the tree at
`root`; nullifier recomputed and matched; each output commitment recomputed; `outAmount <
2^248`; `sum(in) + publicAmount == sum(out)`; nullifiers distinct; `extDataHash` squared
(bind only). Groth16, BN254, Powers of Tau 16.

Build: `cd circuits && npm run build` → `build/transaction.wasm`, `build/transaction.zkey`,
`build/verification_key.json`, `../contracts/src/Groth16Verifier.sol`.

  donate), holder-reward runs (pot, next run, holders, link to snapshot JSON), donation
  epochs (ring, cause, amount, leaf index), harvest receipts (public / shielded), every row
  linked to BscScan.
- `/donate` — causes registry (register a cause with a shielded key), rings, next rotation
  countdown, pot per ring, "Donate publicly" / "Donate privately" (in-pool transfer).
- `/docs` — the Sapling docs structure rewritten for zkBNB (fees, roots, harvest, stages,
  rootstock, holder rewards, donation rings, shielded pool, dark pools (`/docs/darkpool`: the
  hidden / public lists of §3.9 verbatim in spirit, the relayer's powers, the `relay()`
  signature model, the `darkPool` / `darkVaultImpl` addresses), trust model, addresses).

Footer: "Coins can go to zero. Roots exist only while there is BNB in them. Nothing here is advice."

## 6. Keeper (`keeper/`)

Node + viem, one process, env-configured:

- `sweep`: for Orchard coins, call `sweepTax` when `accruedTax` is worth ≥ `minSweep`.
- `rewards`: for Holders-mode coins, when `pot ≥ minPot` and ≥ 1 h since last run, wait a
  random 0–60 min, snapshot balances from `Transfer` logs, build Merkle tree, publish JSON
  (`snapshots/<coin>/<runId>.json`) and call `postRun`.
- `rotate`: call `settle(ringId)` for every ring whose epoch has elapsed and pot > 0.
- `buyback`: call `buybackAndBurn` when `rootstockPot ≥ minBuyback`.
- `rings-feed`: optional indexer writing `rings.json` for the web if no RPC log scanning.

## 7. Deployment order

Poseidon T3, Poseidon T4 → Groth16Verifier → ShieldedPool → FeeRouter(treasury, recovery)
→ Roots(feeRouter, pool) → HolderRewards(feeRouter, pool, keeper) → DonationRotator(pool,
treasury) → Launchpad(feeRouter, router) → wire (`feeRouter.setModules`, `setLaunchpad`,
`launchpad.setRoots`) → DarkVault impl(launchpad, pool, router) → DarkPool(pool, launchpad,
vaultImpl) → plant `$ZKBNB` with `isRootstock` → `feeRouter.setRootstock(GROVE)`.
On a chain that is already deployed, `script/DeployDarkPool.s.sol` adds the last two and writes
`darkPool` / `darkVaultImpl` into `deployments/<chainId>.json` (§3.9).

## 8. Shared zk client library — `circuits/lib/grove-zk.mjs`

Plain ESM, runs in Node and the browser (deps: `circomlibjs` buildPoseidon, `snarkjs`,
`@noble/curves` x25519 + `@noble/ciphers` xchacha20poly1305 (or tweetnacl), `ethers` v6
for keccak/abi). Used by `web/` and `keeper/` and by the circuit tests. Exact API:

```ts
export const FIELD_SIZE: bigint; export const ZERO_VALUE: bigint; export const LEVELS = 20;
export async function init(): Promise<void>;           // builds Poseidon once
export function poseidon(inputs: bigint[]): bigint;
export class Keypair {
  privkey: bigint; pubkey: bigint;                      // pubkey = poseidon([privkey])
  encPriv: Uint8Array; encPub: Uint8Array;              // x25519 derived from keccak(privkey)
  static random(): Keypair;
  static fromPrivkey(privkey: bigint): Keypair;
  static fromSignature(sigHex: string): Keypair;        // privkey = keccak(sig) % FIELD_SIZE
  static fromAddress(addr: string): Keypair;            // view-only: pubkey + encPub, no privkey
  address(): string;                                    // "zkbnb1" + hex(pubkey 32B || encPub 32B)
  sign(commitment: bigint, merklePath: bigint): bigint; // poseidon([privkey, commitment, merklePath])
  encrypt(bytes: Uint8Array): Uint8Array;               // to this keypair's encPub (ephemeral x25519)
  decrypt(bytes: Uint8Array): Uint8Array;               // needs encPriv
}
export class Utxo {
  constructor({ amount, keypair, blinding?, index? });  // blinding random if omitted
  amount: bigint; blinding: bigint; keypair: Keypair; index: number | null;
  commitment(): bigint;                                  // poseidon([amount, pubkey, blinding])
  nullifier(): bigint;                                   // poseidon([commitment, index, sign(commitment, index)])
  encrypt(): Uint8Array;                                 // keypair.encrypt(abi(amount, blinding))
  static decrypt(keypair, bytes, index): Utxo;           // throws if not ours
}
export class MerkleTree {
  constructor(levels?: number, leaves?: bigint[]);
  insert(leaf: bigint): number; bulkInsert(leaves: bigint[]): void;
  root(): bigint; path(index: number): { pathElements: bigint[]; pathIndices: number };
  get elements(): bigint[];
}
export async function prepareTransaction(args: {
  tree: MerkleTree; inputs?: Utxo[]; outputs?: Utxo[];   // padded to 2 with zero-amount UTXOs
  extAmount?: bigint; fee?: bigint; recipient?: string; relayer?: string;
  wasm: string | Uint8Array; zkey: string | Uint8Array;  // snarkjs artifacts
}): Promise<{ proof: ProofStruct; extData: ExtDataStruct; publicSignals: string[] }>;
// ProofStruct/ExtDataStruct match ShieldedPool.Proof / ShieldedPool.ExtData exactly (bigint fields,
// extDataHash as 0x-hex bytes32, encryptedOutput as 0x-hex bytes).
export function hashExtData(extData): bigint;            // keccak(abi.encode(tuple)) % FIELD_SIZE
export function calculatePublicAmount(extAmount: bigint, fee: bigint): bigint;
export function scanNotes(args: {
  keypair: Keypair;
  commitments: { commitment: bigint; index: number; encryptedOutput: string }[];  // NewCommitment events
  depositsFor: { pubKey: bigint; amount: bigint; blinding: bigint; index: number }[]; // DepositFor events
  nullifiers: Set<bigint>;                                                           // NewNullifier events
}): { unspent: Utxo[]; spent: Utxo[] };
```

Shielded address format: `zkbnb1` + 128 hex chars (pubkey big-endian 32 bytes, then x25519 encPub
32 bytes). Causes store `shieldedPubKey` (uint256) and `encryptionKey` (bytes32) on-chain.
